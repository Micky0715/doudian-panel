# 盖亚 Playwright 探测边界

`scripts.gaia_browser_probe` 使用独立的 `gaia_browser_data/` 持久化浏览器目录，不复用抖店登录目录。

它只打开盖亚渠道商品页、切换抖音渠道、打开“双维成色发品”弹窗、展开店铺下拉、将数量设为 1、触发文件选择器但**不选择文件**，最后点“取消”。脚本没有“确定”点击、文件上传或商品创建代码。截图保存在 `panel_data/gaia_listing/browser_probe/`，浏览器目录与截图目录权限限制为仅当前用户可读写；两者含登录状态或商家页面信息，不应同步或提交到版本库。

运行：`PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 -m scripts.gaia_browser_probe --login-wait 120`。首次使用需要在弹出的独立窗口登录盖亚。成功只证明导航和控件可操作，不代表盖亚上传或抖店草稿同步成功。

真实文件控件验收使用 `scripts.gaia_browser_upload_preflight`：它先复核批次、模板、映射和输出文件哈希，再精确选择批次店铺、回读数量 1、把生成的 Excel 放入文件控件并检查“确定”是否可用，随后只点击“取消”。该脚本没有点击最终“确定”的代码，不会创建或发布商品。

真实上传使用单独的 `submit.py`，不能通过修改本探测脚本来绕过边界。表单准备已抽到 `upload_form.py`；预检包装器不接受提交回调，始终取消。

2026-09-24 文件回读修复：准备阶段和最终确认共用 `file_attachment.py`，只检查当前弹窗中的上传列表或原生文件选择框，不再通过整个弹窗的文本包含文件名来判定。兼容组件清空 `input.files`、但列表仍保留文件的情况；列表要求唯一文件名精确一致、无上传中或失败状态，连续两次稳定回读。原生文件仍存在时另外核对名称和大小；若此前已看到上传列表，最终列表消失不能回退为仅凭旧 input 通过。未知状态、重名多项、文件冲突均停止，店铺/数量/哈希检查和一次提交意图记录保留。

回读成功/失败日志包含批次、阶段、实际文件名及状态；失败时保存 `file_readback_error.json` 和截图后再取消。此修复已用离线 DOM 用例及模拟最终点击验证，真实页面上传与最终受理尚待实测；没有自动重跑旧失败批次。

面板由 `application/upload_execution.py` 启动后台执行：检查文件与店铺、原子记录确认、占用盖亚专用浏览器、上传副本、点击前再次核对、记录提交意图，然后最多点击一次确定。同批次重复启动不会重复提交。页面明确反馈只记为“盖亚受理”；缺少反馈记为“待核对”，不自动重试，不调用抖店发布。本次仅通过模拟提交测试，尚未进行真实最终提交验收。
