# 盖亚发品模块边界

本目录负责“型号输入 → 价格规则表查 ID → 双维成色模板生成 → 上传执行状态”。不负责抖店商品编辑、图片上传或抖店发布。浏览器动作独立放在 `integrations/gaia_browser/`。

## 2026-10-13 当前链路（后文旧阶段记录不代表当前按钮行为）

1. 选择店铺、一个或多个成色，填写手机型号，一行一个；可写 `苹果,iPhone 17 Pro` 或完整品牌型号。每个标品 SKU 按所选成色分别生成一行；盖亚成色编码为 99新→`99`、95新→`95`、9新→`90`、准新机→`100`。
2. 只点一次“开始执行”：使用面板当前已校验的空模板和直播货架价格规则映射版本，只用明确国行记录。读取 `拍拍标品skuId`，不是货品 ID 或价格。更换模板、映射表等操作在默认收起的“高级设置”中；页面显示当前文件、版本和更新时间。
3. 一个明确品牌/型号的颜色、容量 ID 全部展开；重复 ID 只写一次。若部分型号未找到或有跨品牌/型号歧义，一键流程只用明确匹配的型号继续生成本批文件，并在逐行结果和批次摘要保留跳过原因；不猜选、不把整个价格规则目录作为发布清单。全部型号都失败或展开后超过 2000 个标品 ID 时仍阻断。未匹配型号不会包含在盖亚上传和后续分期商品 ID 处理中，修正后须单独发起新批次。
   同一映射版本里，若盖亚曾在已提交批次中明确返回“根据标品skuId未查询到类目信息”，该标品 ID 会在新匹配中剔除并显示来源批次；同型号其他 ID 不受影响。已生成的旧文件若仍含这类 ID，则上传前阻断并要求重新生成。此规则只针对明确的无类目拒绝，不把其他平台错误一概视为无效 SKU，也不会自动重试被拒批次。
4. 填写 A:H，逐行回读并校验源文件/输出哈希。盖亚曾对仅 90 行、包含两个型号的文件反馈“超过 500 行”，所以工作表行数不足以解释其服务端计数。新批次采取保守策略：同一型号的全部 SKU × 成色行保持在同一份文件，不同型号分别生成文件；每份仍不得超过含表头 500 行。一次点击会按份顺序上传，每份明确受理且新商品 ID 核实后才上传下一份；任何回执不明立即停止，已上传的份不可整批重试。单一型号自身超过单文件容量时仍在提交前阻断，以免把同型号拆成两件商品。单次任务目前最多检查 2000 行组合。同一 SKU 在不同成色行出现属于预期。浏览器上传时保留每份文件不变，用带批次号的唯一文件名选择上传，避免连续任务都显示 `gaia_upload.xlsx` 而无法区分。
5. 上述校验通过后自动调用 `POST /batches/<id>/start`，绑定店铺和文件哈希；后台打开专用浏览器，选店、数量 1、上传副本，回读后点击确定。不再要求第二次点击，可能需要在专用窗口登录。
6. 付款方式为全款或多选 6/12/24 期，二者互斥。分期按所选最高期数处理盖亚价格规则；上传前只读确认同店铺 ID、同场域、同期数的唯一启用规则。全款与分期均在提交前读取同店同型号渠道商品快照；盖亚明确受理后只读回查新增商品，核实店铺、所选场域、型号、创建时间等字段，并按预计商品数收齐唯一商品 ID。找不到商品时标为人工核对，不把“导入成功”误报为商品创建或抖店草稿成功，也不自动重传。多行 SKU 可以属于同一件商品，不按 Excel 行数误判商品数。
7. 使用受控的价格上浮官方模板生成独立副本，只导入最高期数对应规则。现有直播货架 12/24 期比例分别核验 4.3%/9%；6 期及直播间规则须现场唯一匹配、核验启用与比例，并在提交前后保持规则名和比例不变。点击前持久化分期提交意图；仅明确受理才报告已受理。找不到/歧义商品、规则或回执时停止，不猜选、不自动重试。
8. 前端轮询进度。重复启动复用原批次，盖亚浏览器同时只执行一批，不改动抖店四并发调度。

`gaia_accepted` 仅表示页面明确成功反馈，**不代表逐行创建完成或抖店发布成功**。自动分表目前已通过离线生成和模拟顺序上传测试，尚未用真实多文件批次验收；分期自动导入的最终点击也尚待真实端到端验收，不能把本地单测当作平台写入成功。`config/gaia_execution.json` 控制启动入口，`GAIA_LISTING_V1_ENABLED=0` 可紧急关闭。“开始执行”包含真实盖亚提交及所选分期的自动导入；高级设置的“仅生成文件”不会触发提交。

日常一键流程只读面板受控版本，不扫描服务器下载目录。旧的下载目录发现/导入接口保留供兼容和排查，不参与一键启动。模板首次可从面板原有受控模板目录迁移，之后上传须通过唯一模板结构校验；映射表仍须通过国行筛选。版本文件不可变并逐次校验 SHA-256；新上传未通过校验时旧版本保持不变。单批预览和生成记录模板路径/哈希与映射版本，后续更新不会悄悄替换该批输入。

新增边界：`application/model_resolution.py` 展开指定型号；`application/upload_execution.py` 管理执行、文件锁和状态；`integrations/gaia_browser/upload_form.py` 准备并回读表单；`submit.py` 负责一次最终点击和反馈；`upload_preflight.py` 始终只取消、不提交；`assets/gaia-workspace.js` 编排一键流程与表单；`assets/gaia-execution.js` 管理上传启动、进度轮询、防重入与恢复。抖店前端不承担盖亚编排。

### 停止任务（2026-09-24）

“开始执行”旁的“停止”不在禁用的参数 fieldset 内。准备阶段停止后，等待当前读取或生成请求结束，不再执行下一步；如刚生成批次，则取消同一批次。浏览器阶段调用 `POST /api/gaia/batches/<id>/stop`，校验店铺及输出文件哈希，并在同一批次锁内与提交意图互斥。停止成功后状态为 `cancelled`，活动浏览器先显示 `stopping`，安全退出后为 `stopped`；保留 Excel 和审计记录。

本地停止不能撤回盖亚任务。提交意图已记录时，停止返回 409，继续回读原批次结果，不重试确定、不改成已取消。等待登录、下拉搜索、文件回读和最终提交前均检查停止状态；正在等待的单次浏览器操作会在返回/超时后的安全点退出，不强杀其他任务。前端丢弃停止前发出的旧轮询响应，防止已停止状态被覆盖。

停止交互修正（`gaia-stop-2`）：准备/上传阶段显示“停止任务”，点击即显示“正在停止…”；服务确认取消且浏览器退出后显示“已停止”。已进入提交阶段显示“已提交，无法撤回”，按钮下方直接说明原因，不再只禁用按钮。准备阶段取消失败、停止响应丢失时不会误报“已停止”；显示“停止待确认”并查询原批次，阻止重复启动。启动请求因增加抖店分期只读预检，HTTP 超时为 60 秒；停止和状态查询为 10 秒。超时不等于服务端任务取消；不会自动补发启动/停止请求。停止回读确认取消后，即使原停止响应丢失，也按服务端取消状态显示。关闭页面清理计时器和未完成的状态请求，不代表后台任务自动停止。

提交反馈保留 `observed_feedback` 和 `gaia_submit_feedback` 日志，识别“没有对应 goodsId”等拒绝提示。盖亚明确拒绝的「标品 ID＋成色 ID」会在同一映射版本、再次选择该成色时排除；已生成的旧文件若含该组合也会在提交前拦截。新批次预检按官方原表的「标品 ID＋双维成色→货品 ID」逐组核验，只跳过缺失或曾被明确拒绝的组合，其余组合照常生成；预览与批次摘要记录跳过原因。盖亚模板本身不接收货品 ID，货品 ID 只用于上传前核验，不能替代成色 ID。已提交的原文件不会原样重提；只见普通提示、未取得成功回执时仍为 `manual_required`。

运营确认：原表「双维成色」为“全新仅拆封”或“准新机”时，均对应盖亚模板的准新机成色 ID `100`。两者只在同一标品 ID 下核验货品存在性，不把其他标品 ID 的货品借来使用。

2026-10-14 增加安全续传：仅在盖亚明确指出唯一一组「标品 ID＋成色 ID」缺少 goodsId、且拒绝后两次只读回查均证明目标店铺/型号没有新增渠道商品时，生成新的子批次，只剔除这一组后继续上传其余行。原批次和文件保留，不会原样重提；最多隔离 12 组，任何回执不明确、回查失败或发现部分创建都会停止并交人工核对。父批次保存子批次 ID、跳过组合及最终核实商品 ID；跳过组合会在同映射版本的后续匹配中排除。此逻辑只处理盖亚草稿创建，不触发抖店发布或活动报名。

离线验收：`python3 -m scripts.gaia_model_workflow_canary` 在临时目录用真实映射与模板生成并回读，不打开浏览器、不提交。回归：`python3 -m unittest discover -s tests -p 'test_gaia*.py'` 和 `node --test tests/test_gaia_execution_ui.cjs`。

## 旧阶段记录

阶段 B2 已接入模板预览、生成和下载。型号映射只接受 `.xlsx`/`.csv`；上传成功后保存独立版本、SHA-256 与有效标品 SKU 数。“抖音直播货架货品价格规则数据导出（货品维度）”是映射来源，不是上传模板；由高级设置上传一次后供后续任务复用。导入时若存在“标品名称”列，只保留明确包含“国行”的数据；非国行或未标注行数及 SKU 数会记入版本审计信息。源文件不会被修改。生成时必须另外提供本次明确选择的 standardSkuId 清单，不能把整个参考目录误当成铺货任务。系统重新校验模板、映射版本和成色 ID，只复制空模板到独立输出目录，写入 A:H 后逐行回读并记录输出哈希。前端“开始”会串联当前受控模板与映射版本检查、预览、生成和上传前校验；盖亚网页最终提交和抖店交接仍保持独立阶段。

接口：`POST /api/gaia/model-mappings/import-download` 只接收下载目录中唯一识别的货品维度导出；`POST /api/gaia/model-mappings/resolve` 复用本地图库的品牌/型号归一化规则，只返回候选，不会在同型号的多个 SKU 中猜选。`POST /api/gaia/batches/preview` 返回前 20 行及总行数；`POST /api/gaia/batches/generate` 要求携带预览返回的 `source_sha256` 和 `quality_id` 作为 `expected_source_sha256`、`expected_quality_id`；`GET /api/gaia/batches/<id>/download` 在文件哈希一致时才提供下载。`GET /api/gaia/qualities/status` 可查看成色 ID 是否配置。盖亚导入专用成色编码由运营确认：99新 → `99`，95新 → `95`（2026-09-24），9新 → `90`，准新机 → `100`（2026-10-10），写入模板 E 列；不得使用抖店属性 3320 的选项 ID `18972`/`18954`。成色配置每次读取，修改后即时用于新预览/生成；旧预览及旧批次被成色一致性校验拦截，须重新生成，不覆盖历史 Excel 或提交记录。

阶段 C 的准备检查已实现为只读 `GET /api/gaia/batches/<id>/handoff-preflight?shop_id=<店铺ID>`：重新核对批次状态、店铺、数量 1、源模板与型号映射哈希、当前成色 ID、输出文件哈希；只在全部一致时返回交接清单和稳定幂等键。它不确认批次、不打开盖亚、不上传文件。浏览器上传仍须在已登录页面可连接、真实成色 ID 和型号映射已核实后单独验收。

2026-09-13 已增加独立 Playwright 页面探测 `integrations/gaia_browser/probe.py`。在真实已登录盖亚页面验证了“抖音渠道 → 双维成色发品 → 批量操作弹窗”、店铺下拉、数量 1、文件选择器和取消按钮；未选择店铺或文件，也未点击“确定”。它尚未接入面板任务或任何真实上传流程，详见 `integrations/gaia_browser/README.md`。

非表格部分已补上本地批次生命周期控制：`POST /api/gaia/batches/<id>/cancel` 要求目标店铺和 2～300 字取消原因，在原子读改写下仅允许盖亚提交前的状态取消；重复取消只返回原结果、不重复记事件。已提交批次返回冲突，绝不能被本地标为取消。取消保留生成文件供审计，不删除、不上传。`GET /api/gaia/batches/<id>` 可查看状态和事件。这里的“取消”只是阻断未来由本程序发起的提交，不是盖亚网页中的撤销。

抖店草稿关联目前只有保守匹配器，尚未接入自动交接：必须有同店、全量分页、校验和正确的提交前后草稿快照、新增商品的详情回读（品牌、型号、成色），以及盖亚回执中逐行对应的商品 ID。标题相似、草稿数量相同，甚至同期唯一同型号草稿，都不能单独作为成功证据；缺少回执关联或同一草稿对应多行时进入待核对。真实详情回读和盖亚受理回执关联仍待下一阶段实现。

| 列 | 规则 |

## 价格上浮导入准备

面板优先读取下载目录最新的官方价格上浮模板，校验 A1“抖音商品ID（必填）”和 B1“导入失败原因”，再保存面板受控副本；也可手动更换模板。生成时仅写副本 A 列，不覆盖官方原文件。

仅同店、有效场域、6/12/24 期、已核实本批抖店商品 ID 数量与预计商品数一致时，才允许生成导入表。规则列表按名称中唯一的【店铺 ID】、结尾期数和场域匹配；直播间规则名须明确包含“直播间”，货架规则不得包含该字样。同 ID、同期数、同场域若有多个规则，或启用状态、上浮比例无法核实，则停止而不猜选。浏览器只读探测规则列表、编辑页策略名称和“导入商品ID”入口，不修改比例或已有商品。

历史批次若只有“导入成功”提示、没有逐行商品 ID，仍无法通过关联门槛，不能对其自动导入价格规则或报名活动。不能把标品 SKU ID、标题或同时间新增商品猜作本次创建的抖店商品 ID。

## 分期免息活动报名（2026-10-12 新增）

新批次选择任意分期时，启动请求必须包含运营填写的完整活动卡片名称；全款不接受活动名称，也不进入价格规则或活动报名。活动名称、所选期数集合、最高盖亚规则期数及本批已核实的抖店商品 ID 固定在批次记录中。只有盖亚发品与对应价格规则导入都已受理，才启动抖店浏览器。浏览器严格核对当前店铺、唯一同名活动卡片，强制“部分商品参与”，仅勾选运营选择的 6/12/24 期；之后按本批 ID 逐一添加商品。全店报名、重名、未找到商品或已报目标期数均停止。旧批次的单值 24 期仍按原有 12+24 期语义恢复，不改变历史批次。

活动提交前记录不可重复提交的意图；提交后用只读 `cpaypromotion.queryProductCpayPromotionAndShopStatus` 回读每个商品的报名期数和同一活动 ID。回读完整才标记 `activity_phase=verified`；不完整或提交响应丢失则 `manual_required`，禁止自动重试。抖店分期浏览器与备用上架共用 `panel_data/browser_profiles/listing/<店铺ID>/`，同一店铺登录一次即可；不复用旧的 `doudian_cpay_browser_data` 或 `cpay/<店铺ID>/`。首次使用在执行电脑运行 `python3 -m scripts.doudian_browser_login_window --shop-id 636781 --purpose listing`（按目标店铺替换 ID），确认当前短 ID 并关闭窗口；启动批次前会只读核对登录店铺及唯一活动卡片，未就绪时不会先创建盖亚商品。同一店铺的上架与分期任务不能同时占用浏览器资料。当前浏览器定位仅完成页面只读检查与离线测试，尚未用真实新建商品做端到端提交验收；正式放量前应先用一件商品小批量验证。
